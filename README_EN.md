# Hono + Prisma PostgreSQL Production Template

A production-ready TypeScript REST API skeleton built with Hono + Prisma v7, with built-in JWT authentication.

## Features

- **Auth System**: Register / Login / Token Refresh / JWT Middleware, bcrypt hashing + Refresh Token rotation
- **Strict Typing**: TypeScript strict mode, Zod v4 validation for request bodies & environment variables
- **Code Quality**: ESLint + Prettier, enforced `import type` usage
- **Structured Logging**: JSON line output, zero external dependencies
- **Prisma v7**: `prisma.config.ts` + `@prisma/adapter-pg` adapter for direct PostgreSQL connection
- **Process Safety**: Graceful shutdown on SIGTERM/SIGINT, uncaughtException / unhandledRejection capture

## Quick Start

```bash
npm install

# Create local environment file
cp .env.example .env
# Edit .env with your DATABASE_URL and JWT_SECRET

npm run prisma:generate
npm run prisma:migrate
npm run typecheck
npm run build
```

## API Endpoints

All auth endpoints are mounted under `/auth`:

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `POST` | `/auth/register` | No | Register a new user (email + password ≥ 8 chars) → returns `{ accessToken, refreshToken }` |
| `POST` | `/auth/login` | No | Login → returns `{ accessToken, refreshToken }` |
| `POST` | `/auth/refresh` | No | Refresh tokens (provide refreshToken) → returns new token pair (old token invalidated) |
| `GET` | `/user/profile` | Bearer JWT | Get current user info `{ id, email, createdAt }` |

### Example Requests

**Register**

```bash
curl -X POST http://localhost:4399/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "password123"}'

# Response 201
# {
#   "accessToken": "eyJ...",
#   "refreshToken": "xxx-xxx-xxx"
# }
```

**Get User Profile**

```bash
curl http://localhost:4399/user/profile \
  -H "Authorization: Bearer <accessToken>"

# Response 200
# { "id": "uuid", "email": "user@example.com", "createdAt": "..." }
```

## Environment Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `APP_ENV` | Runtime env (`dev` / `test` / `prod`), auto-maps `NODE_ENV` | `dev` |
| `NODE_ENV` | Node.js mode, automatically derived from `APP_ENV` | `development` |
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://user:pass@host:5432/db` |
| `JWT_SECRET` | Access token signing key (≥ 32 chars) | `your-jwt-secret-at-least-32-chars` |
| `JWT_REFRESH_SECRET` | Refresh token signing key (≥ 32 chars, not currently using JWT format) | `your-refresh-secret-...` |
| `PORT` | HTTP server port | `4399` |

## Environment Management

The app loads the corresponding `.env.{APP_ENV}` file based on `APP_ENV`, then fills in missing entries with `.env`.
`dotenv` uses `override: false`, meaning platform-injected environment variables always take priority over file values.

Priority: **Platform / cross-env > `.env.{APP_ENV}` > `.env`**

### Local Development

```bash
cp .env.example .env          # Dev database
cp .env.example .env.test     # Point DATABASE_URL to test database
```

- `npm run dev` — reads `.env.dev` (falls back to `.env`)
- `npm run dev:test` — reads `.env.test`

### Deployment (Test / Production)

Inject `APP_ENV` and `DATABASE_URL` via platform secrets; no files needed:

| Environment | `APP_ENV` | `NODE_ENV`    |
| ----------- | --------- | ------------- |
| Development | `dev`     | `development` |
| Test        | `test`    | `test`        |
| Production  | `prod`    | `production`  |

All `.env` and `.env.*` files are ignored by `.gitignore` to prevent secrets from entering Git.

## Security Design

- **Passwords**: bcrypt salted hashing (cost factor 10), never stored in plaintext
- **Refresh Tokens**: SHA256 hashed before storage; raw tokens only returned to client, irreversible server-side
- **Token Rotation**: Old refresh token immediately deleted on each refresh, preventing replay attacks
- **Timing Attack Prevention**: Dummy bcrypt compare executed when user not found during login, preventing email enumeration via response timing
- **JWT Middleware**: `Authorization: Bearer <token>` auto-validated, using HS256 symmetric signing
